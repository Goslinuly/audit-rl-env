# auditgym v1.1.0

Исправления по сверке с требованиями хакатона. Версии: пакет 1.1.0, генератор 0.2.0,
среда 1.0.0, оценщик 1.1.0, config 1.0.

- **ID эпизода больше не выдаёт seed.** Раньше `episode_id` считался только из seed и
  перебирался за миллисекунды. Теперь это sha256 опубликованных записей.
- **Eval: диагностика оценщика не попадает в процесс агента.** В `grade_log` остаются
  только итоговые числа (P, R, F1, награда, TP/FP/FN); полный разбор оценщик пишет
  в отдельный файл (`grader_log_path` или `AUDITGYM_GRADER_LOG`).
- **Оценщик 1.1.0.** Валюта, которой нет в эпизоде, и лишние поля внутри вывода больше
  не обнуляют весь ответ до −1: такой вывод считается ложным срабатыванием. ID без
  префикса (`INV-…`) принимается, если в эпизоде ровно одна такая запись.
- **Готовые журналы:** `artifacts/trajectories.jsonl`, `results.csv`, `leak_report.json`
  (4 политики на train+dev), `make artifacts` для пересборки.
- **Разбор сбоев с цифрами** (DESIGN.md §7, `make failure-analysis`): Reconciler с
  отключёнными правилами (часовой пояс, курс выходного дня, дубли, частичная оплата)
  падает до F1 0,24–0,75; ложные срабатывания приходятся на отвлекающие случаи генератора.
- `python -m auditgym.generator transform` — тот же эпизод с новыми ID и порядком строк.
- `requirements.lock`, Dockerfile ставит зависимости из него; команды `docker build/run`
  в README; `make test` работает.
- Названия компаний выглядят как настоящие; веб-интерфейс без внутренних терминов.

Проверка: `make check` или
`docker build -t audit-rl-env . && docker run --rm --network none --cpus 2 --memory 4g audit-rl-env`.
Данные вымышлены, обучение весов не проводилось.
