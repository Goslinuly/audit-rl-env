# Changelog

## 2.0.0 — определения проверок жюри от 20 ноября

Версии: пакет 2.0.0, генератор 0.3.0, среда 1.1.0, оценщик 2.0.0, config 1.0.

- `judge_adapter.py`: `generate_episode`, `make_env`, `score_episode`; описание в `docs/judge.md`,
  сценарии D01–D20 в `configs/judge/scenarios.json`, тесты всех таблиц в `tests/judge/`.
- Оценщик 2.0.0: точное сравнение ID и валюты, допуск по типам (τ = 0, у `fx_conversion` 1),
  неверное содержание вывода — один FP вместо −1, лексикографический tie-break. Нестрогие
  правила 1.1.0 (ID без префикса, регистр, пробелы) отменены.
- Среда 1.1.0: лимит действия 1 МБ вместо 64 КБ (допустимый ответ из 30 выводов с кириллицей
  раньше не принимался); 60 с идут от начала `reset`; закрытый процесс запускается из любого скрипта.
- Генератор 0.3.0: необязательный `allocation_mode`. Записи и эталоны эпизодов не изменились,
  в `provenance.json` поменялась только версия.

## После 1.0.0

- `python -m auditgym.generator transform IN OUT --remap-seed N --shuffle-seed N` — тот же
  эпизод с новыми ID и порядком строк для парных проверок; результат проходит verify.

- Генератор 0.2.0: `episode_id` считается из публичных записей (sha256), а не из seed —
  раньше seed восстанавливался из ID перебором. Записи и эталон не изменились, поменялись
  только ID; эпизоды и SHA256SUMS пересобраны.

- Генератор 0.1.1: названия компаний вида «Zhetysu Consulting Ltd» вместо слогов.
  Случайный поток не изменился: в эпизодах поменялись только `company_name` и версия
  в provenance, ошибки и эталон те же. Эпизоды и SHA256SUMS пересобраны.
- Веб-интерфейс: понятные подписи без внутренних терминов («Проверки» вместо
  «Эпизоды», месяц и набор вместо `train_03`), документ-доказательство показан
  полями с суммами, а не JSON; пункты меню в одну строку.

- Упаковка и разбор сбоев: `requirements.lock` с точными версиями всех зависимостей
  (Python 3.11, Linux), Docker ставит зависимости из него; `make test` вызывает
  `python -m pytest`, в pytest добавлен `pythonpath = ["."]`.
- `artifacts/`: траектории, результаты и leak report четырёх политик на train + dev
  (`make artifacts`), сводка `summary.md`.
- Абляции Reconciler (`auditgym/policies/ablations.py`, `tools/failure_analysis.py`,
  `make failure-analysis`) и измеренная таблица в DESIGN.md §7; существующие политики
  не изменены.
- В `results.csv` добавлены колонки `tp`, `fp`, `fn`, `generator_version`.
- `python -m auditgym.runner.demo --metrics PATH` пишет только JSON метрик;
  `docs/demo/participant4.json` пересчитан под новые ID эпизодов (.cast не менялся,
  метрики совпадают).
- README: инструкция для контейнера, полная таблица метрик, раздел ограничений;
  DESIGN.md: убраны заглушки, обновлены §7 и §8.

## Package 1.0.0 — release

- Добавлена публикация по тегу v1.0.0 после повторных проверок точного релизного исходника.
- Релизный архив содержит обычные и контейнерные отчёты, wheel, демо и SHA256.
- Статус verified_release требует совпадающего хеша исходников и подтверждённых
  ограничений Docker: без сети, 2 CPU, 4 GiB.
- Отрицательные тесты проверяют отказ при устаревших/неполных отчётах и неверных лимитах.
- Версии и реализации командных generator/env/grader не изменены.

## Package 0.2.0 — participant 4 integration

- Добавлены четыре политики, адаптированные к командному AuditEnv и Grader.
- Runner получает страницы из result.items и числовую оценку из grade_log.
- Добавлены JSONL/CSV, автоматический leak-scan и версии компонентов в результатах.
- Добавлены 320 приёмочных проверок и отдельные проверки train/eval и JSON Schema.
- Добавлены полная переносимая проверка, Docker CI с ограничениями, отчёты CI,
  проверка установленного wheel, архив кандидата и терминальное демо.
- Все 10 командных схем включены в wheel без изменения корневых контрактов.
- Сохранён отдельный cyberpunk-прототип; существующий веб-обозреватель не заменён.

Компоненты участников 1–3 сохранены: generator 0.1.0, env 0.1.0, grader 1.0.0,
config 1.0. Собственная параллельная реализация среды и оценщика не добавляется.
